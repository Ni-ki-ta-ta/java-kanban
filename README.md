## О проекте

Менеджер задач позволяет создавать, редактировать, удалять и отслеживать выполнение задач. Поддерживается три типа:

| Тип | Описание |
|---|---|
| `Task` | Обычная задача |
| `Epic` | Большая задача, объединяющая несколько подзадач |
| `Subtask` | Подзадача, входящая в состав эпика |

## Функциональность

### Управление задачами

- Создание, обновление и удаление задач, эпиков и подзадач.
- Статусы: `NEW`, `IN_PROGRESS`, `DONE`.
- Получение задач по идентификатору и списками.

Статус эпика считается автоматически по статусам его подзадач:

| Подзадачи | Статус эпика |
|---|---|
| Нет подзадач или все `NEW` | `NEW` |
| Все `DONE` | `DONE` |
| Во всех остальных случаях | `IN_PROGRESS` |

### История просмотров

- Хранится порядок просмотра задач, повторные просмотры не дублируются.
- Реализована на двусвязном списке и `HashMap`, добавление и удаление работают за O(1).

### Планирование по времени

- У задачи есть время начала и продолжительность, время окончания считается автоматически.
- Задачи, пересекающиеся по времени, не принимаются.
- Список задач в порядке времени начала: `getPrioritizedTasks()` (задачи без времени начала в него не попадают).
- Время эпика вычисляется по подзадачам: начало — самое раннее, окончание — самое позднее, продолжительность — сумма.

### Сохранение данных

- `FileBackedTaskManager` записывает задачи и историю в CSV-файл после каждого изменения.
- `FileBackedTaskManager.loadFromFile(file)` восстанавливает задачи, связи эпиков с подзадачами, историю и счётчик идентификаторов.

### HTTP API

- Весь функционал менеджера доступен по HTTP, данные передаются в JSON.
- Сервер построен на встроенном `com.sun.net.httpserver.HttpServer`.
- `Duration` и `LocalDateTime` сериализуются через собственные адаптеры Gson.

## Быстрый старт

**Требуется:** JDK 21.

Система сборки (Maven/Gradle) в проекте не используется, а `*.jar` не хранятся в репозитории, поэтому библиотеки нужно подложить вручную.

1. Клонируйте репозиторий:

   ```bash
   git clone https://github.com/Ni-ki-ta-ta/java-kanban.git
   cd java-kanban
   ```

2. Создайте папку `lib` в корне проекта и положите в неё:
    - `gson-2.9.0.jar`;
    - для тестов — jar-файлы JUnit 5.14.0 (список указан в `java-kanban.iml`).

3. Откройте проект в IntelliJ IDEA и запустите нужный класс:
    - `ru.practicum.http.HttpTaskServer` — HTTP-сервер на порту `8080`;
    - `ru.practicum.Main` — консольная демонстрация работы менеджера.

То же из командной строки.

Windows (PowerShell):

```powershell
javac -encoding UTF-8 -cp lib/gson-2.9.0.jar -d out/production (Get-ChildItem -Path src -Recurse -Filter *.java).FullName
java -cp "out/production;lib/gson-2.9.0.jar" ru.practicum.http.HttpTaskServer
```

Linux / macOS:

```bash
javac -encoding UTF-8 -cp lib/gson-2.9.0.jar -d out/production $(find src -name "*.java")
java -cp out/production:lib/gson-2.9.0.jar ru.practicum.http.HttpTaskServer
```

> HTTP-сервер по умолчанию работает на `InMemoryTaskManager`: данные хранятся в памяти и после остановки сервера не сохраняются.

## Архитектура

Приложение состоит из трёх слоёв:

- **model** — задачи, типы и статусы.
- **manager** — бизнес-логика: управление задачами, проверка пересечений, история, сохранение в файл.
- **http** — обработчики запросов и сериализация JSON.

Интерфейс `TaskManager` описывает все операции над задачами. Его реализации:

- `InMemoryTaskManager` — хранение в памяти;
- `FileBackedTaskManager` — наследник `InMemoryTaskManager`, который дополнительно сохраняет состояние в файл.

Экземпляры создаёт фабрика `Managers`. История просмотров вынесена в отдельный интерфейс `HistoryManager`.

## Формат файла сохранения

Первая строка — заголовок, затем задачи, пустая строка и в последней строке идентификаторы задач из истории просмотров:

```csv
id,type,name,status,description,duration,startTime,epic
1,TASK,Купить молоко,NEW,В магазине у дома,30,2026-11-04T10:00,
2,EPIC,Переезд,NEW,Организовать переезд,60,2026-11-04T12:00,
3,SUBTASK,Собрать коробки,NEW,Книги и посуда,60,2026-11-04T12:00,2

1,2,3
```

`duration` указывается в минутах, `startTime` — в формате ISO-8601. Для подзадачи в последнем столбце хранится `id` эпика.

> Ограничение: запятые и переводы строк в названии и описании задачи не поддерживаются.

## HTTP API

Сервер запускается на порту `8080`.

| Метод | Endpoint | Описание |
|---|---|---|
| GET | `/tasks` | Все задачи |
| GET | `/tasks/{id}` | Задача по ID |
| POST | `/tasks` | Создать или обновить задачу |
| DELETE | `/tasks/{id}` | Удалить задачу |
| GET | `/epics` | Все эпики |
| GET | `/epics/{id}` | Эпик по ID |
| GET | `/epics/{id}/subtasks` | Подзадачи эпика |
| POST | `/epics` | Создать или обновить эпик |
| DELETE | `/epics/{id}` | Удалить эпик |
| GET | `/subtasks` | Все подзадачи |
| GET | `/subtasks/{id}` | Подзадача по ID |
| POST | `/subtasks` | Создать или обновить подзадачу |
| DELETE | `/subtasks/{id}` | Удалить подзадачу |
| GET | `/history` | История просмотров |
| GET | `/prioritized` | Задачи в порядке времени начала |

`POST` создаёт объект, если `id` в теле равен `0` или не указан, и обновляет существующий, если `id` передан.

### Коды ответов

| Код | Когда возвращается |
|---|---|
| `200` | Успешные `GET` и `DELETE` |
| `201` | Успешный `POST` |
| `404` | Объект не найден |
| `405` | Метод не поддерживается |
| `406` | Задача пересекается по времени с существующими |
| `500` | Внутренняя ошибка сервера |

### Формат данных

| Поле | Тип | Описание |
|---|---|---|
| `id` | число | Идентификатор (при создании не указывается) |
| `name` | строка | Название |
| `description` | строка | Описание |
| `status` | строка | `NEW`, `IN_PROGRESS` или `DONE` |
| `duration` | число | Продолжительность в минутах |
| `startTime` | строка | Время начала, ISO-8601: `2026-11-04T10:00:00` |
| `epicId` | число | Только для подзадач: `id` эпика |

### Пример

Создание задачи:

```bash
curl -X POST http://localhost:8080/tasks \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Реализация HTTP API",
    "description": "Разработка API для менеджера задач",
    "status": "NEW",
    "duration": 60,
    "startTime": "2026-11-04T10:00:00"
  }'
```

Получение списка задач по времени начала:

```bash
curl http://localhost:8080/prioritized
```

## Тестирование

Тесты написаны на JUnit 5 и лежат в папке `test`. Запускаются из IntelliJ IDEA: ПКМ по папке `test` → **Run 'All Tests'**. Они покрывают:

- создание, обновление и удаление задач, эпиков и подзадач;
- расчёт статуса и времени эпика;
- проверку пересечений по времени и сортировку по приоритету;
- сохранение и восстановление из файла;
- менеджер истории просмотров;
- HTTP API.

Проверка pull request'ов выполняется автоматически через GitHub Actions (`.github/workflows/api-tests.yml`).

## Планы развития

- Перейти на Maven или Gradle, чтобы не подкладывать библиотеки вручную.
- Валидация запросов: код `400` для некорректного JSON и идентификаторов.
- Экранирование спецсимволов в CSV.
- Возможность запускать HTTP-сервер поверх `FileBackedTaskManager`.
